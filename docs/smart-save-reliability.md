# Smart Canvas 保存可靠性修复

开发基线为 `18101b14b563d2c4170d2acd46416d77187094db`，分支 `codex/smart-save-reliability`。这是开发验收文档，不是生产发布记录。未改普通 Canvas 保存实现、服务端版本检查、任务 ledger、模型适配器或维护工具。

## 保存入口与协议

`smart-save-coordinator.js` 是 Smart 页面唯一的写入协调器。`scheduleSave()` 登记当前序列化草稿；`saveCanvas()` 请求刷新队列。debounce、Prompt 编辑器关闭、模型/参数、位置/节点/连接、撤销重做、结果回填和原任务恢复原有调用均经过这两个入口。Smart 源码只有一个画布 PUT 构造点。日志删除这类辅助写操作通过 `externalWrite()` 串行预约，避免与整画布 PUT 竞争。

- 编辑修订 `rev` 与确认修订 `ack` 分开。快照深拷贝，包含节点、连线、标题、设置、视口和日志；发送时固定 canvas id、epoch、revision 和 `base_updated_at`。
- 同一页面最多一个 PUT 在途。B 确认只确认 B；若 C 已产生，使用 B 的确认版本再保存 C。重复关闭/显式保存不重发相同快照。
- `base/version` 是已确认基线，`remote` 是观察到的远端状态；WS/meta 不会偷偷提升脏草稿的写入基线。
- `observe()` 仅在没有未确认修改/活动时替换远端完整画布；不再用节点或图片并集掩盖删除、同字段修改冲突。
- 所有异步核对 GET 也绑定修订、版本、epoch 和读取序号。旧 GET、旧 PUT 或上一页面的响应不能回退当前状态。
- 保存传输有 30 秒总时限；失败/超时不自动重发。只有 GET 与原发送快照精确相等、版本确实前进时，才能认定原写入已确认。服务器未变不被当作请求已经结束的证据。

## 可见状态与草稿处理

正常自动保存全程静默：未保存、保存中和已确认保存只保留为内部状态，不创建状态卡片、角落文字或 Toast。发现本机草稿时只显示工具栏「草稿」入口、实际数量及需要处理的标记，初次进入、刷新和重新进入均默认收起。用户点击后才展开原恢复、保留、导出和服务器核对操作；展开或收起本身不写画布、不清草稿、不更改版本基线。保存冲突、结果待核对、保存失败、维护、登录失效和本机草稿保护失败仍显示独立异常提示。保存协调器、修订确认、dirty、草稿保护和未确认修改的离开提醒不变；静默不代表已保存。

409 保留最新本地草稿、最后确认基线和远端快照，暂停自动重存。用户可以：

1. **导出当前草稿**：下载当前页面草稿 JSON，去掉任务/nonce/运行 History 等绑定；不会创建或运行任务，也不是服务器保存成功证明。该文件用于保留和人工复制内容，不提供自动重新导入/执行。
2. **放弃本地修改并加载服务器**：再次确认后新 GET，读取期间若又有编辑则放弃该操作。不会强制 PUT 或修改服务器版本。
3. **核对服务器**：处理保存响应丢失；不以一次 GET 随意抬高未合并草稿的基线。

浏览器草稿复用 `instance-storage.js` 的用户/实例命名空间，再按 canvas id + 随机页面/草稿分支隔离。单条最多 2 MiB、每画布最多 20 个其他分支；不自动淘汰未确认内容，不复制媒体二进制或凭证。存储拒绝、配额/格式异常会显示保护不可用，并提供导出。浏览器清理后无法保证恢复。

重新进入先等待真实身份确认。发现旧草稿显示恢复选择；恢复后核对原基线。若页面又收到原任务结果，可明确选择“保留旧草稿，继续保存当前页面”，旧分支不删除。不会让旧分支覆盖新回填结果。采用其他标签的草稿后，仅当该分支仍与采用时完全相同，才在最新确认/明确放弃后清理；不会删掉另一标签后来产生的修改。

正常离开有未确认修改时弹出保护提示。认证撤销后的强制登录导航不被离开提示阻塞；匹配画布 PUT 的 401 在 scoped storage 失活前记录“已拒绝”，不误作仍在途请求。刷新仅停止本页图片任务等待，不再调用远端任务取消接口；主动“取消生成”的行为保留，LLM 离开清理保留。

## 验证与重复方法

- `node --test tests/test_smart_save_coordinator.cjs`：直接运行产品协调器，独立断言；不从被测 builder 生成 expected。
- `.venv/bin/python -m unittest discover -s tests` / `./scripts/check.sh`：保留原 889 项；增加协调器和实际资源白名单两个 Python 入口。Node 子用例另计，不重复算成 Python 项。
- `tests/manual_smart_save_browser.py`：临时真实 Gateway、Supervisor、两个真实 Instance、合成登录账号、假 Key、本机严格 mock。只绑定 loopback；数据在新临时目录。用浏览器正常登录输出的 origin，在真实编辑器操作。
- 测试进程 stdin 接受 `delay`（延迟真实写入后的响应）、`drop`（写入后截断 JSON）、`reject`（应用接收前 401/503）、`model-delay`、`status` 和 `finish`。未匹配 mock 请求拒绝；不会请求真实 Provider。
- `status` 把合成画布/请求证据写入临时 `browser-state.json`，控制台只输出摘要。`finish` 正常关闭临时服务并保留证据。

## 边界与后续发布

不实现自动三方协作合并、不做服务器端草稿副本/自动导入、不证明任意跨浏览器组合兼容。完全禁用全站存储、浏览器数据被清除、多个设备离线协作不承诺恢复。辅助日志写入响应不明时保守暂停，不能通过盲目 GET/PUT 宣称结束。

本轮不部署。后续单独授权后沿用现有维护/限定封口流程；旧授权不复用。需切换新 release，Supervisor 的新实例路径指向该 release，现有 Instance 加载新的静态白名单和资源缓存；Gateway 的资源版本缓存也须按原发布流程重新加载。客户端重新加载 Smart HTML、Smart JS/CSS、协调器和共享 session 模块。不能只替换磁盘 JS 就宣称旧进程或已有标签已更新。不需数据迁移，不改注册、容量、Provider/Key 或版本文件。
